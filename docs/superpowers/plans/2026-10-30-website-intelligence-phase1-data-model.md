# Website Intelligence — Phase 1: Data Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a user-managed `Website` entity and a `WebsiteCrawlJob` entity
(DB models + Alembic migration + CRUD/lifecycle API) that the Phase 2+
crawler will drive, following this repo's existing `Source`/`AcquisitionJob`
patterns exactly.

**Architecture:** Two new SQLAlchemy models in `src/chanakya/db.py`
(`Website`, `WebsiteCrawlJob`), one autogenerated Alembic migration, a new
FastAPI router `src/chanakya/desk_websites.py` mirroring
`desk_acquisition.py`'s structure (module-level dict helpers, `APIRouter`,
registered in `server.py`), registered under `/api/websites*`. No crawler
logic yet — `WebsiteCrawlJob` rows are created and transitioned by this
API only through plain status writes in this phase; Phase 2 wires in the
actual crawl execution.

**Tech Stack:** Python 3, SQLAlchemy 2.0, Alembic, FastAPI, pydantic,
pytest (existing stack, no new dependencies).

**Spec:** `docs/superpowers/specs/2026-10-30-website-intelligence-design.md`
(§5 Phase 1; reuse points in §2).

## Global Constraints

- DateTime columns are naive UTC, written via `now_utc()` from `.timeutil`
  (per `db.py` module docstring convention).
- String columns use the `String(length)` helper (VARCHAR on SQLite, TEXT on
  PostgreSQL) — never raw `sa.String`/`_SAString` directly in new models.
- IDs are `f"web_{uuid.uuid4().hex[:16]}"` for websites and
  `f"wcj_{uuid.uuid4().hex[:16]}"` for crawl jobs, matching the
  `job_{uuid...}` convention in `acquisition/job_manager.py:80`.
- Every new route lives behind the desk's existing app-wide auth
  (`server.require_desk_auth`) by virtue of being registered the same way
  `acquisition_router` is — no separate auth gate in the new router.
- Category values are a closed enum validated at the API boundary:
  `government_procurement`, `government_department`, `nhai`, `gepnic`,
  `state_eprocurement`, `psu`, `company_website`, `other` (brief §3).
- No fabricated data: list/get endpoints return only what's persisted; an
  empty table returns `{"websites": []}`, never a placeholder row.

## Review Focus

- Deleting a website that has crawl job history: must not orphan
  `WebsiteCrawlJob` rows or raise an unhandled FK error — enforced via
  `ON DELETE CASCADE` or an explicit check, decided and tested in Task 2.
- Duplicate base URLs: two websites with the same `base_url` are not
  auto-deduplicated or rejected (the connector/job layer already dedupes
  by URL per job, not per website) — but must not crash create; tested in
  Task 3.
- Invalid/unknown `category` on create or update: must return 400, not a
  500 from an uncaught pydantic/enum error — tested in Task 3.
- Cancel/pause/resume called on a website crawl job in a terminal state
  (`succeeded`/`failed`/`cancelled`): must return 409, matching
  `desk_acquisition.cancel_job`'s existing behavior, not silently no-op —
  tested in Task 4.
- Listing jobs for a website that doesn't exist, or getting a website that
  doesn't exist: must return 404, not an empty list that looks like "no
  jobs yet" — tested in Tasks 3 and 4.
